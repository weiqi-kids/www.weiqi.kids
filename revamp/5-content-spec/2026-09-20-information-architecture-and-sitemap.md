版本：0.3（2026-09-20）  
狀態：資訊架構規格草稿；完整樹狀地圖以 [`2026-09-20-site-tree-v2.md`](2026-09-20-site-tree-v2.md) 為有效版本。本文件的棋聚與課程成果路徑已同步，不代表已開始 Astro 實作。

## 1. 網站的三條服務線

網站同時服務三個不同需求：

1. **協會**：說明主辦組織、協會成員、歷史活動與組織資料。
2. **好棋寶寶棋聚**：說明實體圍棋聚會、主題講座、友誼對局、新手交流與活動報名。
3. **AI 共學營**：說明標準課程、講師、報名、教學、實作論壇與學習成果；AI 應用工具、產業供應鏈情報與研究發表是課程主題或案例，不是平行的協會服務線。

協會是共學營的主辦者，但「協會」與「共學營」不使用同一個頁面或同一組內容混在一起。

## 3. 成員資料的位置

協會成員資料放在：

```text
協會 → 成員 → 個別成員資料
```

建議 URL 結構：

```text
/association
/association/members
/association/members/[member-slug]
```

成員資料可以包含：

- 姓名
- 職務與專業身分
- 組織／品牌
- 個人簡介
- 與協會的關係或職務
- 經本人授權公開的連結、照片與介紹資料
- 參與的課程、講師身分或公開作品連結（有對應公開權限時）

這些資料是公開成員介紹，不是會員帳號資料的完整呈現。登入方式、付款紀錄、會員到期日、課程權限與私密聯絡資料不放在公開成員頁，也不進公開 sitemap。

## 3A. 會員、講師與學員的關係

不把會員、講師、學員做成互斥的三種成員分類：

- **會員**是協會身分；有效期限一年一續會。
- **講師**是經過課程參與與管理員審核後取得的角色；講師也可以同時是會員與其他課程的學員。
- **學員**是某一門課的參與角色；同一個人可以參加多門課，也可以在不同課程擔任不同角色。
- **活躍會員**是系統授權判斷用的狀態，表示會員費在有效期間內；不作為公開成員分類，也不公開會員到期日。

公開頁面使用「協會成員」作為主分類，個別成員可顯示經本人同意的角色標籤，例如「講師」。課程頁與論壇頁再顯示該人在特定課程中的「講師」或「學員」角色。

## 3B. 好棋寶寶棋聚與共學營的界線

- **好棋寶寶棋聚**是協會的實體活動服務線，包含實體聚會、主題講座、友誼對局與新手交流。
- **AI 共學營**是固定 1 堂教學、3 堂實作、1 個月的付費課程服務。
- 棋聚參加者不會因參加活動自動取得共學營會員、課程或論壇資格。
- 共學營學員也不必參加棋聚；兩邊可以共享成員與講師資料，但報名、出席、費用、照片與活動紀錄分開保存。
- 舊站「好棋同樂會」的內容可作為棋聚歷史與活動素材；舊站與目前狀態衝突的「尚未啟動定期實體棋會」文字必須改寫或封存，不能直接搬入現行頁面。

## 4. 成員與歷史資料的界線

- 成員姓名與已授權公開的個人資料，主要位置永遠是「協會 → 成員」。
- 不建立「會員歷史資料區」來存放仍屬於成員的個人介紹。
- 活動、合作與協會發展事件可以放在「協會 → 歷史資料」，但頁面中的成員連結仍指向成員區。
- 成員資料更新或撤回公開時，更新成員頁與相關公開引用；不把人名複製成另一份歷史會員資料。

## 6. 導覽呈現建議

主導覽可分成：

- **AI 共學營**：課程、講師、參加方式、公開作品。
- **協會**：協會介紹、成員、活動與歷史資料。
- **登入／我的課程**：登入後才出現。

首頁可以同時放協會主辦說明與共學營主行動，但成員介紹不應被埋在課程頁或歷史資料頁內。

## 6A. 建議的實際呈現順序

首頁不把所有舊內容平鋪出來，而是讓訪客先理解現在的三條服務線：

1. **協會是誰**：協會定位、成員與主辦責任。
2. **好棋寶寶棋聚**：目前的實體活動、下一場活動與參加方式。
3. **AI 共學營**：標準課程、講師、費用、報名與實作論壇。
4. **公開知識**：經確認仍有用的圍棋／AI 知識與歷史教材。
5. **歷史資料**：活動、合作與協會發展的回顧，不與現行服務混在一起。

建議主導覽為：

```text
協會　棋聚　AI 共學營　公開知識　登入
```

「歷史資料」可放在「協會」底下；不放入主導覽第一層，避免訪客把舊活動誤認成目前服務。

主導覽入口不等於所有內容都在同一層。公開內容保留以下父子階層：

```text
協會
├── 成員
├── 好棋寶寶棋聚
│   ├── 即將舉辦
│   ├── 活動場次
│   └── 活動紀錄
├── 活動與合作
└── 歷史資料

AI 共學營
├── 說明
├── 課程／主題
│   └── 單一課程
├── 講師
│   └── 單一講師
├── 公開作品／推薦
└── 公開知識
```

## 8. 完整路由清單

### 8.0 課程論壇的位置與權限

每一門共學營課程都有自己的論壇，論壇是該課程的登入後子頁，不是全站共用討論區：

```text
AI 共學營
└── 課程／主題
    └── 單一課程
        └── 課程論壇
            ├── 文章／作品／圖片／側拍
            ├── 講師回覆
            └── TTQS 課程佐證關聯
```

- 未登入者只能看到公開課程介紹與「登入後進入論壇」入口。
- 已開通該課程的學員，登入後可以自行加入該課論壇並發文、上傳與回覆。
- 課程關聯中的所有核准講師，可以依其課程角色管理或回覆該課程論壇；協會管理員可以管理所有課程論壇。
- 文章、作品、圖片、側拍與回覆都是該課程的內容與可能的 TTQS 佐證。
- 課程結束後，原課程成員仍可依原權限查看、發文、上傳與互動。
- 協會本身不建立全站共用論壇；棋聚活動也不使用共學營課程論壇。

## 9. Sitemap 分組規則

公開 XML sitemap 可拆成下列 sitemap index：

```text
/sitemap.xml
├── /sitemap-static.xml       # 協會、條款、隱私、服務線入口
├── /sitemap-members.xml      # 授權公開的成員頁
├── /sitemap-gatherings.xml   # 公開棋聚介紹與場次
├── /sitemap-courses.xml      # 公開共學營課程與講師
├── /sitemap-knowledge.xml    # 公開知識與核准歷史教材
└── /sitemap-showcase.xml     # 作者同意公開的推薦作品
```

以下永遠不列入公開 sitemap：

- `/account/**`
- `/admin/**`
- 完整技能單張與未公開教材
- 課程論壇、學員附件、側拍原始檔與私密佐證
- 報名、付款、收據、會員到期與帳號資料
- 未經權利確認的歷史資料

## 10. URL 與內容生命週期

### 公開內容

`draft` → `review` → `published` → `updated` → `archived` 或 `withdrawn`。

公開頁撤回時，從 sitemap 移除並依 URL 計畫處理 canonical／redirect；原始資料與撤回事件保留。

### 棋聚場次

`draft` → `registration_open` → `registration_closed` → `completed` → `archived`。

已完成場次可以留在活動紀錄，但不可繼續顯示為即將報名。

### 共學營課程

`draft` → `under_review` → `published` → `registration_open` → `in_progress` → `review_pending` → `closed`。

課程結束後，公開課程介紹可以保留；完整教材與論壇依課程權限保留，不轉成公開頁。

## 11. Sitemap 驗收

- [ ] 所有公開 URL 都有唯一 canonical。
- [ ] sitemap 只包含 200、可公開爬取且允許索引的 URL。
- [ ] 登入後、管理後台、付款與私密附件不在 sitemap。
- [ ] 每個 URL 的頁面主題與 title／H1 一致。
- [ ] 成員、棋聚、課程、知識與歷史頁能從公開導覽或 sitemap 找到。
- [ ] 已撤回、已轉址、noindex 或不存在的 URL 不留在 sitemap。
- [ ] `lastmod` 反映實際內容更新，不因重新匯出或爬蟲訪問而虛假更新。
- [ ] sitemap 與 redirect、canonical、robots 規則互相一致。
