# 舊站資料轉移工作清單

版本：0.1（2026-09-20）  
狀態：待逐項審核；本清單不授權刪除、公開或搬遷任何資料。

## 使用方式

逐頁資料以 [舊站逐頁 inventory](2026-09-20-legacy-page-inventory.md) 為主表。本表的 153 筆是從 repository 找到的來源，不代表要全部轉移，也不是已核准的內容清單。本清單是執行順序與驗收關卡；每一筆來源都要有處置、去處、理由與負責確認者，資訊不足時維持待確認，不自行補完。

## 1. 來源凍結與備份

- [ ] 記錄舊站 Git commit、建置版本、Docusaurus 設定與部署分支。
- [ ] 匯出目前所有繁體中文 routes、文件、`src/pages/`、`src/data/`、圖片與靜態附件清單。
- [ ] 保存原始檔案、原始 URL、檔案雜湊與匯出時間。
- [ ] 保存目前 sitemap、robots、canonical、redirect 與 SEO 產物。
- [ ] 保存目前網站首頁、重要入口與外部連結的可讀快照。
- [ ] 確認備份可以在不連線舊站的情況下重新讀取。

## 2. 每筆資料必填欄位

對 inventory 的每一筆資料補上：

- [ ] `source_path`、`old_url`、標題與內容類型。
- [ ] 原始內容版本、最後更新時間與來源 commit。
- [ ] 目前主張、承諾、人物、組織、作品與外部連結。
- [ ] 是否包含個資、醫療、法律、付款、內部資料或影像。
- [ ] 作者／資料負責人／需要確認的人。
- [ ] 既有流量、GSC 索引、外部連結與 canonical 證據。
- [ ] 新站角色與處置理由。

## 3. 處置分類

每筆資料只能先選一個候選分類，最後由內容負責人確認：

- [ ] **A 轉寫到新站**：改寫成協會、共學營、公開知識、課程素材或成員內容。
- [ ] **B 歷史資料**：保留原始資料與來源，放歷史索引或受控保存區。
- [ ] **C 封存不公開**：內部 SOP、付款、未核實資料、隱私或權利不足內容。
- [ ] **D 淘汰**：重複、空白、失效且無保存價值；保留處置記錄。
- [ ] 未能判定的項目維持「待確認」，不轉移、不刪除、不公開。

## 4. 必須優先審核的內容群組

- [ ] 舊首頁、協會介紹與現行定位。
- [ ] 收費、會員、免費參加與招生承諾；移除或改寫與現行規則衝突的內容。
- [ ] 成員資料；保留在成員區，確認欄位、現況與更新方式。
- [ ] 活動、合作、地點、人物與作品；判斷是現行資料還是歷史資料。
- [ ] 好棋寶寶棋聚／好棋同樂會：分開盤點現行場次、活動報名、出席、照片與歷史紀錄，不併入 AI 共學營。
- [ ] 教材、圍棋／AI 知識與技術文件；判斷能否轉公開知識或課程技能單張。
- [ ] 內部 SOP、財務、收據與未公開資料；不得進公開 sitemap，但要盤點哪些內容轉成共學營管理後台的流程與欄位需求。
- [ ] 翻譯與多國語系資料；本階段只保存來源，不建立新語系頁面。

## 5. 權利與公開狀態

對人物、機構、作品、影像與引用內容逐項記錄：

- [ ] 是否已有公開授權或需要重新確認。
- [ ] 作者／本人／機構是否同意新站用途。
- [ ] 公開層級：公開、登入後、課程內、管理員限定或不公開。
- [ ] 是否允許改寫、裁切、重新編排、加上新站標籤或建立新 URL。
- [ ] 撤回公開後要移除哪些快取、索引與推薦展示。
- [ ] 權利不足時改為歷史封存或不公開，不直接搬到新站。

## 6. URL 與 SEO 處置

每個保留或改寫的舊 URL 補上：

- [ ] `old_url` 與 `new_url`。
- [ ] 301、canonical、noindex、保留原 URL 或移除。
- [ ] GSC 曝光／點擊與外部連結證據。
- [ ] 新頁面是否能承接原搜尋意圖。
- [ ] 舊頁面主張是否已改成現行共學營規則。
- [ ] redirect 測試、canonical 測試與 sitemap 檢查。

沒有替代內容或證據時，不自行設定 301 或 410。

## 7. 內容轉寫與資料建置

- [ ] A 類內容完成繁體中文轉寫。
- [ ] 教材素材依「問題／原因／解法／建議流程」整理成技能單張候選。
- [ ] 成員資料轉入成員區，不建立會員歷史資料區。
- [ ] B 類資料保存原始檔、來源 URL、版本與調閱權限。
- [ ] C 類資料放入受限保存區，不進公開建置與 sitemap。
- [ ] 內部 SOP 轉成管理後台的操作規則、狀態、角色與稽核需求，不直接把舊文件原樣當成新流程。
- [ ] 財務與收據資料轉成報名、匯款確認、補件、退款／撤銷（如適用）與收據紀錄需求；不公開原始付款附件。
- [ ] D 類資料保留處置紀錄與原始雜湊，不直接刪除證據。
- [ ] 圖片與附件重新命名、建立 metadata、確認來源與權利。

## 8. 轉移執行驗收

- [ ] 每筆資料都有唯一 migration ID。
- [ ] 每筆資料都有來源、處置、去處、理由與確認狀態。
- [ ] 新站沒有舊的免費、無會員費或錯誤招生承諾。
- [ ] 歷史資料不會被誤當成現行課程、會員或學員帳號。
- [ ] 私密、未核實與權利不足資料不會出現在公開頁面或 sitemap。
- [ ] 所有圖片、附件、連結與引用可追溯到來源。
- [ ] 轉移後逐頁比對內容、URL、權利、SEO 與公開狀態。
- [ ] 發現問題時可由 migration ID 回退，不修改舊站原始資料。

## 10. 需要使用者逐組確認的順序

1. 成員資料：哪些現行欄位保留、哪些需要更新。
2. 活動／合作／作品：哪些保留為歷史，哪些可轉為公開內容。
3. 教材／知識／技術：哪些轉成公開知識，哪些只作課程素材，哪些只保存。
4. 舊首頁、收費與招生文案的改寫範圍。
5. 歷史資料的公開層級與調閱位置。
