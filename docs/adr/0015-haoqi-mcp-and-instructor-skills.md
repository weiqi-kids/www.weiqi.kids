# ADR 0015：好棋寶寶講師 skill、學員 skill 與 MCP

- 狀態：已接受
- 日期：2026-10-08
- 修改：ADR 0014 的「技能單張付費才看得到全部」；成果上架必填由 7 項改為 8 項

## 背景

講師的成果背後是實際在跑的 skill 和流程（下載資料、建網站、定時更新、推導驗證等），光靠對話做不出來。站主要讓講師與學員都能在自己用的 AI 工具裡，不費力地上架、試做、分享作品與心得。學員與講師用的 AI 工具不一定都是 Claude。

## 決策

### 協會提供三樣，講師與學員各裝一次

1. **好棋寶寶講師 skill**：協助講師工作——把自己的專案整理成 repo、建立成果草稿與開團設定、送審新版本、看學員進度、主動擬回覆草稿。
2. **好棋寶寶學員 skill**：與講師的分開——從學員的問題找到成果、照講師的做法在學員自己的帳號建一份、每週整理實作進度、完成時主動整理分享草稿。
3. **好棋寶寶 MCP**：架在協會網站、網站帳號登入，是兩套 skill 對網站做事的管道（找成果、讀講師的做法、存草稿、查進度、登記想學）。只存草稿；送審、報名匯款、發文、同意公開都由本人在網站上確認。

### 講師自己的、學員自己的

- 講師做出成果實際在用的 skill、程式、定時更新設定、網站範本、設定範例、8 項資料、技能單張、授權，放在講師自己的公開 GitHub，是講師成果的一部分。
- 學員不安裝講師的東西：學員的 AI 透過 MCP 讀講師審過的版本，照著在學員自己的 GitHub 與 AI API 金鑰上建一份自己的，定時更新與網站發布都在學員帳號裡跑，費用學員自付。

### 講師

- 全部公開：skill、流程、技能單張，登入就能取得。付費開團買的是講師的陪伴（主題教學與 3 堂實作）。
- 好棋寶寶講師 skill 幫講師把專案整理成 repo：還沒有 repo 的從集中檔案、安裝 git、註冊 GitHub、建立 repo 開始；公開前一定先掃描 API 金鑰、密碼、個人與客戶資料，沒處理完不 push。能讀電腦檔案的 AI 工具（例如 Claude Code）與網頁版都支援，AI 依講師用的工具走不同路。
- 每個新版本都要管理員審過才公開，學員只拿得到審過的版本。審核頁自動整理這個版本會讀寫哪些檔案、連到哪些網站、跟上一版差在哪。
- 授權由講師自選，可以不開放改作；成果頁與 MCP 都要標清楚。
- 成果上架第 8 項必填：自己跑起來要準備什麼（要哪些帳號、大概每月花多少錢、要不要信用卡）。

### 學員

- 主要入口在網站：成果頁依學員的 AI 工具顯示安裝好棋寶寶學員 skill 與 MCP 的步驟，附一句可複製的話，貼進 AI 就照那位講師審過的版本開始試做。成果牆另有一句話，列出相關成果讓學員選一個。
- 第二個入口：已經裝好的人在 AI 裡說出自己的問題，由好棋寶寶對到成果；對不到時經本人同意把問題記下來給講師們看。
- 執行講師的程式前，AI 先列出會讀寫哪些檔案、連到哪些網站，學員同意才跑。
- 學員完成時（第 3 週交成果，或 skill 偵測到學員的定時更新與網站已經跑起來），AI 主動整理好分享草稿（做了什麼、作品連結或截圖、怎麼做的、心得）存到網站，給學員草稿連結；學員在網站上按一次「確定送出」就發到課程論壇。同一頁可勾選「講師認可後同意公開到成果頁」。
- 學員送出後，講師收到推播；講師的 AI 主動擬好回覆草稿存到網站，推播打開的就是那一頁，講師按一次「確定送出」，認可作品也在同一頁按一下。沒用 AI 的講師，那一頁有幾句常用回覆可直接點選。
- 規則不變：AI 只存草稿，所有發文、送審、同意公開都由本人在網站上確認。
- 分享作品與心得兩條路都可以：由 AI 整理成文章發到課程論壇；或放自己的 GitHub、論壇貼連結（講師授權不允許改作時只能走第一條）。公開到成果頁仍需講師認可與作者本人在網站上同意。

## 後果

- showcases 要多存：講師 repo 網址、審過的版本、授權、第 8 項；另需版本送審紀錄與學員問題紀錄。
- 網站要加 MCP 端點與 OAuth 登入（沿用網站帳號），成果頁加安裝與試做說明，管理區加版本審核。
- 要寫兩套 skill（講師、學員）。不支援 skill 的 AI 工具，同樣的引導改由 MCP 提供。
- 協會的 4 組成果要先整理成符合結構的 repo，才能當第一批示範。
